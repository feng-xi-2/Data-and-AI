# PRIME ELS Hypercare KPI skill

Kit root: the folder that contains `config/`, `tools/`, `dist/` (see README.md).

## Rules
- One semantic model holds every configured site, but each replica table has ONE PARTITION PER SITE (static server/db literals) and a `SiteCode` column; the user sees one site at a time through the synced, forced single-select Site slicer in the banner. Never write a cross-site total.
- Never type a site value into SQL, M or DAX. Site values -> `config/site_config.csv`; engine differences -> `config/engine_profiles.csv`; numbers -> `config/kpi_thresholds.csv`; sentences -> `config/rca_rules.csv`.
- PrIME 2022 replica db = `<SITE>_REPLICA`, schema `dbo`; PrIME 2014 replica db = `<SITE>`, schema `prodwms` (no sto_zone, no loc_typ). Detect with `tools/probe_replica_schema.py`.
- Database queries: timeout <= 120 s; run long validations as background jobs.

## Onboard / change a site
**Use the `hypercare-site-setup` skill.** Short version: add a row to the Sites tab of `Hypercare_KPI_Inputs.xlsx` (at most 6 sites) -> `py tools/add_site.py <SITE>`
(apply -> profile replica with evidence -> site check -> validate every query -> build -> `docs/ONBOARDING_<SITE>.md`; `--dry-run` to preview).
Remove: delete the row -> `py tools/apply_inputs.py --apply --confirm` -> rebuild. The manual steps below explain what the profiler does.
1. `py tools/profile_site.py <SITE> --compare` (proposal + evidence + confidence vs the config; rules in `docs/PROFILER_REGRESSION.md`).
2. Fill the row in `config/site_config.csv` (copy the closest site) and `config/line_map.csv`.
   Feature flags: `Has_Production`, `Has_LevelA`, `Has_HOFF`, `Has_SAP_Plan`, `Has_RPM_Master` - set 0 only when the site really has no such process; the queries then return empty typed tables.
   **Auto-profile against BD before leaving a field empty** (read-only probes, all in `Cfg_Site[Notes]` as evidence):
   - Production: where do produced pallets come from? LTA lanes (`LT%` locations, RCV into `PEPNDLTA*`) -> LTA take-away model; work-order receipts (`dlytrn.frstol = wkohdr.wkonum`, UID/RCV) -> work-order model (`PROD_SRC_EXPR` = `wkohdr.prdlin`, `PROD_SCOPE` = EXISTS wkohdr, `PROD_ARRIVED_COND` / `PROD_LEFT_COND` = `c.LTA_SOURCE IS NOT NULL`, line_map = prdlin list).
   - Level A: `locmst.stoloc LIKE 'F0%A'`-style ground-level rack locations; area = `pckwrk_view.srcare` of those picks. No alphabetic level -> `Has_LevelA` 0.
   - HOFF: `locmst.arecod LIKE 'HOFF%'` -> location patterns ending IN / OUT.
   - Excluded zones: the RPM (`%RPM%`) and problem (`PRBL`) zones (2022 `sto_zone_id`, 2014 `arecod`).
   - FG prefix: first digit of work-order output materials; RPM/PM = the rest (Pallets Location / RPM breakdown use NOT LIKE).
   - Line check-in / supply: `oprcod LIKE 'SUP%'` destinations; trailers: `trlract` action codes per trailer (`TTAT_IN_SRC` / `TTAT_IN_RCPT_COND` when TRKNUM is missing -> per trailer + `rcvtrk`).
   - Set `Config_Status` = `AUTO-PROFILED - confirm with site`.
3. `py tools/validate_sql.py <SITE>` - every row `OK` (compile on the engine + execute when the feature is ON).
4. `py tools/build_pbip.py` - must print no `!! BD literal left`, no `numeric columns without a unit rule` and no exception (asserts: every DAX patch hits, no `ALL(<site table>)`, relationship rework matched).
5. Open `dist/ALL_SITES/WH Hypercare KPI.pbip`, click **Refresh on the ribbon** (first time: each new replica server asks for credentials -> **Microsoft account** -> Sign in -> Connect), pick the site in the Site slicer, check **Config & Health** (all PASS). Then run the self-checks:
   - `powershell -File tools/selfcheck_measures.ps1` -> every measure x every site evaluated, `errors=0` (writes `tools/_selfcheck_measures.csv`).
   - `py tools/ui_test_sites.py <PBIDesktop PID>` -> every site x every page through the Site slicer, no visual error text, title = site (screenshots in `_uitest`).
   - Cross-check row counts / KPIs per site with `CALCULATE(..., Cfg_Site[SiteCode] = "<SITE>")` against `validate_sql.py` row counts.
6. `py tools/publish.py [--workspace "<name>"]` (binds each site's gateway connection `MI-<SITE>_REPLICA-...-PaaS-ADHOC` the account can see).

## Sustainable pipeline (fix the query / model / config, never one visual) - from Microsoft skills-for-fabric + data-goblin agentic skills
Public references: (microsoft/skills-for-fabric `semantic-model-authoring`, data-goblin `semantic-model`, `review-report`, `bpa-rules`; TabularEditor/BestPracticeRules).
1. **Config gate** `py tools/site_config_check.py` (live replicas, read-only) -> `docs/SITE_CONFIG_CHECK.md`. FAIL = fix `config/site_config.csv` before building:
   WH_ID must be the busiest warehouse of the replica (a replica can hold several - Jakarta ID01/ID12, Xiqing CN74/CN66/CN88), feature flags must match locations,
   every LOC_*/AREA_* token must match something, replica history depth and trailer codes are reported (inbound RCV*, outbound any other code - BD uses STO).
2. **Build gate** `tools/model_gate.py` (runs inside `build_pbip.py`) -> `docs/MODEL_CHECK.md`. CRITICAL stops the build:
   C1 report field bound to a missing table / column / measure (broken filters are pruned and listed), C2 relationship columns of different data type,
   C3 measure with its own report-day window on a date-related table that keeps the DimDate filter (rows silently dropped).
   RECOMMENDED: format strings, dead inactive relationships (removed), bi-directional, `/` instead of DIVIDE, charts without sort (time axes ascending, others by value), marked date table.
   Other build rules: count cards show 0 (`zero_count_cards`), DimDate marked as date table, calendar ends today + CAL_FUTURE_DAYS, every SQL carries a refresh stamp (no stale Desktop cache), Data Health per WH_ID with replica retention (First_Event_Local) -> label "not in replica (keeps from dd-mmm)".
3. **Tests** (live model, heartbeat every 30 s, never silent) `tools/run_full_tests.ps1`:
   field by field `audit_fields.py` (every column x site: empty / negative / future dates), site by site `visual_replay.py --days 4` (every data visual's own query),
   filter by filter `visual_replay.py --filters 2` (every slicer, real values per site). Status OK / NO ACTIVITY (configured text) / NA (feature off) / EMPTY / NO VALUE / ERROR.
4. Refresh: `refresh_desktop.ps1` = one transaction per site + 3 retries + `refresh.lock` (a second refresh SKIPS, never runs in parallel). Open a model with `open_model.py` (answers the "Sign in to Power BI" cloud prompt, waits for the engine to hold tables).
5. Memory: the all-sites file needs ~1.5 GB; with < 2 GB free RAM use the site files (`dist/<SITE>`).
## Two kinds of output (same config)
- `dist/<SITE>/WH Hypercare KPI - <SITE>.pbip` - **one site loaded**, only that replica's credentials / gateway needed -> the file to share and publish in other people's workspaces.
- `dist/ALL_SITES/WH Hypercare KPI.pbip` - every site loaded, Site slicer switches instantly; needs access to every replica (one missing credential fails the whole refresh).
- Import mode cannot load data on a slicer change, so "load one site at a time" = the site file. `py tools/build_pbip.py [SITE ...] [--all-only]`.
- Site files contain only their site's Cfg_Site / Cfg_LineMap rows (another site's row on a table related to Cfg_Site creates a (Blank) member in the Site slicer).
- End-to-end test of every site file: `py tools/test_site_files.py [SITE ...]` (open, ribbon refresh + credential prompt, partitions, row counts vs fresh validate_sql, 304 measures, every page) -> `_uitest/site_files/site_files_results.json`.

## Sign-in / refresh failures (Desktop)
- "Login failed. The login is from an untrusted domain and cannot be used with Integrated authentication" = a **Windows** credential is stored for that replica server. Azure SQL MI accepts only Entra: File > Options and settings > Data source settings > Global permissions > the `<replica-server>` entry > Clear Permissions, refresh from the ribbon, choose Microsoft account.
- A refresh started by script (XMLA / MCP / auto_refresh) cannot show the sign-in prompt: for a server with no stored credential it falls back to Windows auth and fails / hangs. First refresh of a new server = ribbon.
- One failing partition cancels the whole refresh transaction. Find it with `tools/refresh_each_partition.ps1` (refreshes partition by partition, prints the error).
- Engine type differences: a column that is `int` on PrIME 2022 but text on PrIME 2014 (e.g. zone = `sto_zone_id` vs `arecod`) gives "OLE DB or ODBC error: Type mismatch" -> CAST in SQL + `TEXT_COLS` in build_pbip.
- DAX: never use a reserved word as a variable name ("The syntax for 'key' is incorrect" puts the measure in error). The current engine refuses ~200 words - not only `on` / `top` / `work` / `key` but also `value`, `date`, `rank`, `when`, `where`, `with` and every DAX function name. The list is MEASURED, not typed: `py tools/sync_dax_reserved.py <PID>` (re-run after a Desktop update) -> `config/dax_reserved_words.txt`; build gate **C6** fails on any reserved VAR name. Use short neutral names (`a`, `s`, `k`, `v`) or prefixes (`vTop`). After a build, `INFO.MEASURES()` with an ErrorMessage must return 0 rows; DAX-only fixes can be pushed into the open model with `py tools/apply_measures_live.py <PID> "A|B"` (then rebuild); new measures -> `py tools/sync_measure_types.py <PID>` (snapshot of the engine return type, used by the default-format rule).
- A custom visual (Sankey) shows no 'no data' text: give it a dynamic subtitle that says WHY it is empty (`PM Order Flow Note`: not traceable / too few orders vs PM_MIN_CASES; `PM Pallet Flow Note`), never a silent blank box. A day picked on the Shift day slicer is kept (no fall-back): the slicer filters the truck axis, so the label then says 'clear the slicer to see the last day with completed trucks'.
- Scheduled refresh: `auto_refresh.py --install` creates the task on the grid from 00:00 (`/ST 00:00`, every HOT Every_Minutes) - a task started at an arbitrary minute ran outside the :00 / :30 tier slots (no tier due -> crash); an off-slot run now falls back to HOT. The banner 'next' = the next grid slot of the scheduler clock (NOW - UTCNOW), shown in site time - not last + interval.
- Refresh watchdog: count only Power Query container CPU + outbound source connections as activity - Desktop's own visual / metadata queries keep the ENGINE busy ('Working on it'), which hid a 14-min stall. A locked workstation stalls the first query that needs a new sign-in token (Windows Hello cannot show) - the message says 'WORKSTATION IS LOCKED' (LogonUI running) instead of 'missing credential'.
- Query change on the open model without reopening: `py tools/sync_partitions.py <PID> "Table A|Table B"` builds ALL_SITES into a temp folder, pushes every (per-site) partition M of those tables into the open model and copies their TMDL to dist/ALL_SITES; then `refresh_desktop.ps1 -Tables "Table A"`. New tables / columns / report JSON still need a rebuild + reopen. Do NOT Ctrl+S in Desktop after live TOM edits (apply_measures_live / sync_partitions): the save hung on 'Working on it' with both processes idle (31-Oct) - close and rebuild instead.
- DAX performance: measures share nothing between visual columns - a table with N status-dependent measure columns runs the KPI chain N times per row. Design tables with ONE heavy column per row (Alerts control tower = `Alert Why` with the status icon + actual vs limit + cause, 34 s -> 5-10 s; cockpit `Open Alert Text` = status + actual vs target + action, 13-32 s -> 4-6 s); put the rest of a rule (numbers, prediction, diagnosis, action) in the click-through detail panel, never a colour-rule measure that re-runs the status (the icon carries the colour). Evaluate a rule's KPI with `_rule_ctx()` (iterate the key in Cfg_Threshold: 1.7 s vs 2.9 s per column with TREATAS of SELECTEDVALUE). Do not put both a state text and separate count measures on one card (the counts re-run every rule status). Compute a value ONCE in VARs and derive text / status / colour from it (`KPI Predicted Summary`, `Open Alert Actual`), iterate statuses once into a table VAR (`Overall Alert State`), exit early for rows that cannot have a value. A visual-level "measure is not blank" filter over heavy measures was 10x SLOWER (arbitrarily-shaped filter) - do not use it to "pre-filter" rows. Prove every rewrite with old-vs-new DAX (`DEFINE MEASURE` the old text) on all sites before applying.
- Test runners: `run_dax_batch.ps1` writes `<out>.lock` with its PID - a second batch on the same output stops with exit 5 (stopping a shell does not always stop its child `powershell.exe`; list `Win32_Process` command lines containing `run_dax_batch` and stop orphans by PID).
- **Scripted refresh that never ends = missing credential** (seen 31-Oct after switching Jakarta to the PROD server): Data source settings shows the server with `Type: Not Specified`, the engine waits with 0 source connections. `refresh_desktop.ps1` now prints a heartbeat every 30 s and stops with `STALLED: <site> ... no stored credential for <server>` (exit 4) after `-StallSec` (240 s) without data-source activity. Fix once per server: Transform data > Data source settings > server > Edit Permissions > Edit... > Microsoft account > Sign in (pick the account that has replica access) > Save.

## Process diagnosis pages (where is it stuck, what to do)
- Process model = `config/process_stages.csv` (stage, flow, object, Warn_Min / Crit_Min, Requires token / flag, pallet location Rule with site tokens, action, owner). Status mapping = `trailer_status.csv` / `shipment_status.csv`; RF step mapping = `movement_classes.csv`; bands = `time_bands.csv`. All of them are expanded into SQL at build (`{{PALLET_STAGE_CASE}}`, `{{TRAILER_STAGE_CASE}}`, `{{SHIPMENT_*}}`, `{{MOVE_CLASS_CASE}}`, `{{MOVE_EXCLUDE_LIST}}` in `m_tokenizer.config_blocks`) - never hand-code a status list in SQL.
- Feeds: `Open Trailers`, `Pallets In Flow`, `Shipments` (snapshots, HOT tier) -> calculated table `Flow Items` -> `Cfg_Stage` -> `Cfg_Site`. Pallets on dispatched trailers stay in PrIME stock on the trailer location - excluded by rule `X_TRAILER_OFFSITE` (Flow_No 0). Receiving dock = location-type flag or `AREA_RCV_DOCK` (not `AREA_RCV_STAGE`, which can be a storage area - Minhang BR01-FW).
- Live vs stale: items older than `STALE_HOURS` (72 h) are stale records (purple, inventory-accuracy action), excluded from the live warning / critical counts, the verdict and the Stuck now lists.
- Grouping alignment: every visual of a page must count the SAME objects as its KPI. Trucks belong to the shift day / hour they were completed (inbound at Dispatch, outbound at Close - the TTAT KPI basis); a check-in-hour chart next to a dispatch-day KPI was empty at Xiqing (trucks waited overnight). Arrival views (check-in hour) are a different question - label them as arrivals and keep them on another page.
- Layout rules (enforced): KPI strips list their fields in `tools/kpi_strips.py` (one registry for report_pages, report_diag and the model) and show the display twins `<measure> (strip)` (`[m] + 0`, base unit format + zero section "–") - a multi-row card must never show "(Blank)"; new cards (`cardVisual`) get "–" from the theme (`showBlankAs`, `theme/build_theme.py`); more than ~8 strip values -> two rows. `note()` refuses < 58 px (the caption hides the text row). A hidden sort column in a table gets a one-character header (a word header wraps letter by letter in 8 px and stretches the header row).
- Explained empties for `report_intent.py` live in `config/visual_expectations.csv` (Page / Visual regex + DAX condition evaluated per site and day) - never a site list. The replay and the intent check must run on the SAME data snapshot (no refresh in between), otherwise data that arrived later turns an old EMPTY into a false defect.
- PowerShell: never put `Select-Object -First N` behind a native command you need to finish (build, refresh) - it stops the pipeline and kills the process after N lines.
- Process mining (Process Mining page, `sql/new/Process Edges.sql`): event log = (case, activity, time) for orders (shipment adddte / alcdte / stgdte / loddte + trailer dispatch via stop -> car_move -> trlr, as in the site PrIME report *Loaded Turn Time*), pallets (dlytrn lodnum + movement_classes step) and trucks (trlract TCHKIN / (un)loading status / TCLOSE / TDSP); collapse consecutive repeats, LEAD per case -> edges with cases + median / p95 (server-side PERCENTILE_CONT ... OVER). Weight the Sankey by DISTINCT CASES (one pallet bouncing 169x between two steps at Jakarta), hide edges < PM_MIN_CASES, every edge gets Edge_Kind = Forward / Storage / Back / Side / Open in SQL (`Flow_Role` in movement_classes.csv: IN / PUTAWAY / STEP / SIDE; Side = transfer / other move = extra handling, NOT rework - by step number '7 Transfer -> 5 Pick' looked like a back step; Storage = put-away -> next step = stock waiting for demand, reported as its own verdict sentence and never the bottleneck - it was Xiqing's '1d 10h bottleneck'); the first move after an IN step is relabelled the put-away (sites book put-away as FL_XFR: Minhang / Athens showed no put-away at all); median / p95 OVER CASES (one row per case and hand-off first - a dummy LPN bouncing 1,390x at Minhang made the median 0); the Sankeys use `PM Flow Cases` = Forward + Storage + Open only (the Microsoft Sankey draws loops as duplicated '_SK_SELFLINK' nodes = unreadable), Side / Back stay in the ranked table; bottleneck = Forward edge with the largest cases x median; subtitles show the window / noise floor in numbers, never the config names; open orders / trucks end in 'Open: waiting after X' = stuck now; the order flow is hidden where shipments stay Ready (Orders Flow Used). Sankey = Microsoft certified AppSource visual `sankey02300D1BE6F5427989F3DE31CCA9E0F32020` (roles Source / Destination / Weight; objects labels + linkLabels), registered in report.json by add_pages (gate C4). Truck Gantt = stacked barChart: invisible first series (minutes after the first check-in, white, its labels hidden by a selector) + wait / work / close-out. Per-truck charts (Gantt, Trucks & TTAT segments / bands) use `[Truck Day Start]` = the report shift day once a truck completed in it, else the last shift day with completed trucks (Athens at 07:30 was empty), with a dynamic subtitle `[Truck Day Label]` (count DISTINCT trailers - TTAT has several rows per truck). Dynamic subtitles: `report_pages.subtitle()` (keep the literal title - the test tools read it).
- Inventory: never build an all-site page on *Pallets Location* - it is the BD materials view (excludes FG_PRTNUM_LIKE: Jakarta 111 rows, Xiqing 2). `sql/new/Inventory.sql` aggregates ALL pallets by area / location class / status / age band (config/stock_age_bands.csv -> {{STOCK_AGE_CASE}}); SUM(untqty) must be cast (DECIMAL) - INT overflow at Akashi. - Alerts explain themselves: `Alert Why` (status icon + actual vs the breached limit and target, one [KPI Actual] evaluation, + rule cause), `Alert Numbers` (config/kpi_explain.csv `{DAX|format}` template, measure names checked at build), detail panel `Alert Detail Text` for the clicked rule (how calculated, prediction method, diagnosis). ## Refresh (15 min)
- `py tools/auto_refresh.py --install` -> scheduled task every 15 min; tiers in `config/refresh_policy.csv` (HOT 15, WARM 60, PLAN 240 for Databricks, COLD daily full) for open Desktop models + published models (Service 15-min needs Premium/PPU/Fabric).
- Slow refresh? `tools/profile_refresh.ps1 -Site X` (seconds per table) and `tools/trace_partition.ps1 -Tables "A|B" -Site X` (engine trace: ExecuteSql vs SequencePoint vs commit). Most cost is fixed per partition / transaction - parallelism > 3 does not help.
- Never commit `dataOnly` alone: Desktop shows "Error fetching data" on every visual until a calculate runs. `refresh_desktop.ps1` sends dataOnly + calculate as ONE sequence per site; prove with `tools/watch_refresh.ps1`.
- Time axes always ascending (`report_pages._sort_time_axis` also flips saved Descending sorts); text time labels sort by a numeric key column.
- Column-only visuals ignore the Site filter (column-only SUMMARIZECOLUMNS) -> build adds a hidden `[Rows <table>]` not-blank visual filter.
- Incremental refresh: add a table to `config/incremental_policy.csv` only if every row has an immutable event date and the SQL groups never span midnight (transactions, day/hour aggregates). Trailers (TTAT), pallet journeys (Produced) and live snapshots stay full. Prove it with `py tools/validate_sql.py --inc-check`. Desktop = history + recent partitions (day roll detected from partition RefreshedTime); Service = `build_pbip.py SITE --service` refresh policies.
- Slow query? time its CTEs with the replica helper, then add a hint / window in `tools/m_tokenizer.py` EXTRA (example: RPM breakdown `OPTION (HASH JOIN)` 208 s -> 2 s). Never put a correlated subquery or a window function over a whole history table in a join token (TTAT rcvtrk link: 111 s -> 8 s as an equi-join).

## Accuracy (prove every KPI, every site)

## Site switch safety

## Layout rules (2-Nov)
- Every page: navy strip (Home, title, section + page, refresh) + filter bar (Site | Day | Shift, synced sync groups Site / Day / Shift; window text `[Window Label]`). Never add a page-level day slicer.
- Day measures use the report window: `SHIFT_DAY` gives `s0 = [Win Start]`, `e0 = s0 + [Win Days]` (a measure may not sit inside a CALCULATE filter argument - keep it in a VAR). Tables with a clock hour get `Shift_No` via `config/shift_columns.csv`; `<table>[shift day] = d` filters get the shift automatically (build_pbip.shift_safe). Hour-axis visuals get `[Hour In Window] = 1` automatically.
- Hourly "done" uses the site's own shift-day position `MOD(h - Shift1_Start, 24)` - never `DimHour[Hour Sort]` (default site only).
- Tab order + banner section + Home index come from `config/page_guide.csv` Section; tall pages: `report_diag.TALL` (page height px), Fit to width.
- Z-pattern per page: KPIs -> where (charts) -> why (verdict / root cause) -> detail lists; number the analysis steps in titles (1., 2., ...).
- `tools/layout_preview.py` runs in every build (wireframes in `_uitest/layout/<file>`, docs/LAYOUT_CHECK.md): overlap / off-page / tiny = build fails.
