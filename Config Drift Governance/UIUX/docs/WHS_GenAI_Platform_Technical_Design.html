Eight design areas

1. Data Pipeline

Approved access to WH Data Replicas, PSDH, WCS/WMS, SAP-approved views, NPI sources, and KPI stores. Critical process steps: source onboarding, semantic mapping, query validation, report publication, incident RCA.

Data sources: (1) WCS replica, (2) WMS replica, (3) CDL. Access: follows the standard access management of each data source — agent access does not grant data access. A logged-in user with access to an agent but not to a data source must also apply for that data source's access.

  • Existing: replica registry, SQL reports, M&M transfer pack.
  • To build: source onboarding UI, freshness checks, query result cache, access trace.

2. Semantic Layer

timbr business-term resolution for metrics, dimensions, joins, filters, and access policy. Semantic Layer should sit before raw database and knowledge navigation.

  • Existing/design: Data Strategy and NPI ontology.
  • To build: semantic object registry, golden queries, Timbr deployment pipeline.

3. Knowledge Graph

Graph lineage for RTCIS, PrIME, SDC, PMC, WI, transformations, values, reports, and lessons learned. Complements timbr, not a fallback.

  • Existing: Neo4j export, graph summary, M&M graph.
  • To build: production graph store, graph tests, graph trace UI.

4. Agents, Tools, Skills, Workflows

Supervisor, Data, Knowledge, and Algorithm Agents coordinate tools and skills through governed workflows.

  • Existing: UIUX registry and many Python/SQL tools.
  • To build: tool manifests, skill manifests, workflow logs, approval UI.

5. Citizen developer integration

Personal KB, personal skill, low-code agent extension, connector templates, and UI contribution must be governed but accessible.

  • FY26: prototype and personal skill POC.
  • FY27: production Skill Platform, templates, monitoring, regional scale.

6. Skill Platform

Draft, personal, candidate, approved, published, monitored, retired. Nothing changes other users' answers until approved.

  • Existing: active SKILL.md files.
  • To build: skill store, steward queue, versioning, rollback, retirement registry.

7. Unified UIUX

Home, Warehouse Natural Language Query, assistants, agents, skills, data/knowledge, Design Documents, Knowledge Graph, answer trace, bot widget, Skill Builder, admin views.

  • Existing: static HTML prototype.
  • To build: production APIs, saved sessions, source intake, skill approval, trace dashboards.

8. Use-case delivery

Use cases share the same foundation but add specific logic: Warehouse Natural Language Query, SQL remediation, process discovery, TACO, NPI, MEGA, MEGA Automation KPI, automation troubleshooting.

  • Existing/POC: SQL remediation, Process Discovery, Warehouse Natural Language Query, TACO POC.
  • Design: EU NPI, MEGA. Coming soon: MEGA Automation KPI Assistant.

Governance and quality

Answer quality

Accuracy, completeness, traceability, consistency, freshness, business usability, and policy alignment.

Golden tests

Standard questions, expected answer, trusted source, tolerance, access policy, and product-owner sign-off.

Operational RCA

Track tool calls, fallback events, semantic/graph disagreement, failed queries, and affected assistants.

Platform runtime: MCP and Skill capability module

Source: ARCHITECTURE.en.md. This is the runtime that hosts the agents, tools, and skills above. It adds three sub-modules on top of the Ultimate Platform (pyrogai, pygentic, LangGraph, IPA on AKS).

MCP Server To build

Inbound. Exposes enabled, RBAC-filtered platform flows as MCP tools to Claude Desktop, Copilot Studio, and IDEs. Thin wrapper to FlowController; reuses the existing OAuth callback.

svc-mcp service To build

Outbound. A tenant service (BUILDER kind) that lets platform flows consume external MCP tools, injected via attached_services with two-stage tenant auth and an allowlist.

skills_core Design

Skill SDK implementing the SkillFactory protocol. The MCP Skill wraps external tools as a supervisor-routable skill, registered alongside existing skills.

Key locks: fastmcp pinned to 2.x because langchain-timbr requires uvicorn~=0.34 (ADR-001); Streamable-HTTP transport, no stdio (ADR-002); MCP OAuth reuses /v1/auth/callback (ADR-006); the MCP Server is mounted on the IPA FastAPI app, not deployed standalone (ADR-007).
