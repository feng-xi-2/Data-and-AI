② How to add a new site (PrIME 2022 or PrIME 2014)No SQL / DAX edits - one row in config/site_config.csv, then rebuild the kit.
1
Profile the replica (fills location / area / production patterns): py tools/profile_site.py <SITE>
2
Add a row to config/site_config.csv (copy the closest site of the same engine):
config/site_config.csv - new row
ColumnExampleMeaning
SiteCode / SiteNameNEWSITEkey + slicer / banner name
WMS_VersionPrIME 2022picks the engine profile
ReplicaServerfrom the replica access e-mail
ReplicaDatabaseNEWSITE_REPLICA2022: <SITE>_REPLICA · 2014: <SITE>
WH_ID / UTC_Offset_hXX01 / 8warehouse id, site time zone
Shift1..3_Start / Hypercare_Start6 / 14 / 22shift-day buckets, data window
Has_Production / LevelA / HOFF / SAP_Plan1 / 0 / 0 / 0turn queries on / off
LOC_*, AREA_*, FG_PRTNUM_LIKELT% / RDTSlocation patterns of the site

PrIME 2022

db <SITE>_REPLICA · schema dbo
zones = sto_zone_id · loc_typ flags

PrIME 2014

db <SITE> · schema prodwms
zones = area (arecod) · no loc_typ
Engine differences are applied automatically from Cfg_Engine by WMS_Version.
3
Optional: lines in config/line_map.csv, per-site targets in config/kpi_thresholds.csv (Site = <SiteCode> overrides '*').
4
py tools/validate_sql.py <SITE> → py tools/build_pbip.py → open dist/ALL_SITES/WH Hypercare KPI.pbip → Refresh. The new site appears in the Site slicer, and its own site file dist/<SITE>/WH Hypercare KPI - <SITE>.pbip is built for sharing.
Service: py tools/publish.py; each replica needs its gateway connection MI-<SITE>_REPLICA-...-PaaS-ADHOC (bound automatically).
